# سِجلّ

تطبيق يستخدمه مسوّقو **تكنولوجي للإنترنت** لتسجيل طلبات اشتراك الإنترنت (FTTH) مع مستمسكات المشترك، ومنع تسجيل نفس البيت أو نفس الشخص مرتين.

- قواعد العمل كاملة: [docs/system.md](docs/system.md)
- مبادئ المشروع: [.specify/memory/constitution.md](.specify/memory/constitution.md)
- مواصفات الفيزات: مجلد [specs/](specs/)

## الفيزات المنجزة

| # | الفيزة | ما تقدّمه |

| 001 | هيكل المشروع والدخول | دخول بالهاتف وكلمة السر، ثلاثة أدوار، قفل بعد 5 محاولات، إجبار تغيير كلمة السر، PWA |
| 002 | الحسابات والصلاحيات | إضافة الأدمنية وصلاحياتهم، إدارة المسوّقين (إضافة، تعديل، إيقاف، تصفير كلمة السر)، «حسابي»، صفحة سجل العمليات |
| 003 | أرشيف الحسابات | زر «حذف» للأدمن الرئيسي ينقل الحساب إلى الأرشيف (لا حذف فعلي)، صفحة «أرشيف الحسابات» والاسترجاع |
| 004 | الإعدادات | المناطق والأبراج والفئات (تفعيل/إيقاف، وحذف غير المستعمل)، الأسعار بالدينار، شرائح المكافآت، مدة صلاحية رمز التحقق |
| 006 | قراءة البطاقة الوطنية | بعد رفع الوجهين يقرأ السيرفر البطاقة ويملأ الأسماء والرقم الوطني والرقم العائلي وحقول الظهر (الميلاد، محل الولادة، الإصدار، النفاذ، جهة الإصدار) مع علامة «من البطاقة»، ولا يكتب فوق ما كتبه المسوّق، ويحفظ القراءة الأصلية؛ «أعد التصوير» للصور غير الواضحة، ومطابقة الرقم الوطني مع الشريط الآلي (MRZ)، والبطاقة المنتهية تمنع الإرسال |
| 005 | استمارة المشترك الجديد | صفحة واحدة بحفظ تلقائي كمسودة على السيرفر، صور البطاقة (تصوير أو معرض) مع ضغط على الهاتف ورفع بشريط تقدّم، موقع البيت (GPS أو خريطة القمر الصناعي)، المنطقة والبرج والفئة بالسعرين، هاتف المشترك، النواقص، قائمة المسودات وحذفها، فتح المسودة من جهاز آخر مع تنبيه التغيير |

## المكوّنات

| المجلد | المحتوى |
|---|---|
| `api/` | الخادم: Python 3.12 + FastAPI + SQLAlchemy 2 + Alembic |
| `web/` | الواجهة: React + TypeScript + Vite، تطبيق PWA عربي RTL |
| `ocr/` | قارئ البطاقة (خدمة منفصلة بلا إنترنت): المشروع المفتوح ID_Iraqi_Project برخصة **AGPL-3.0** مع غلاف HTTP صغير؛ انظر [ocr/UPSTREAM.md](ocr/UPSTREAM.md) |
| `e2e/` | اختبارات Playwright للتطبيق كاملاً |
| `deploy/` | إعدادات Caddy (HTTPS وتوجيه `/api` إلى الخادم) |
| `scripts/` | سكربتات الاختبار والنشر |

## المتطلبات

- Docker مع Docker Compose v2 (على ويندوز: Docker Desktop).
- لا تحتاج تثبيت Python أو Node على جهازك لتشغيل التطبيق.

## التشغيل المحلي

```bash
cp .env.example .env          # على ويندوز: copy .env.example .env
docker compose up -d --build
docker compose exec api python -m app.cli seed-demo
```

- افتح `https://localhost` في المتصفح.
- أول مرة سيظهر تحذير من الشهادة، لأن Caddy يصدر شهادة محلية. اضغط «متقدم» ثم «المتابعة إلى localhost».
- لإزالة التحذير نهائياً، ثبّت شهادة Caddy المحلية كشهادة موثوقة:
  ```bash
  docker compose cp proxy:/data/caddy/pki/authorities/local/root.crt caddy-root.crt
  ```
  ثم افتح الملف `caddy-root.crt` وثبّته ضمن «Trusted Root Certification Authorities».

### الحسابات التجريبية (بيانات وهمية)

| الحساب | الهاتف | كلمة السر |
|---|---|---|

| مسوّق تجريبي (بعد `seed-demo`) | `07700000001` | قيمة `DEMO_MARKETER_PASSWORD` |

### أوامر مفيدة

```bash
docker compose logs -f api        # سجل الخادم
docker compose down               # إيقاف التطبيق (البيانات تبقى)
docker compose down -v            # إيقاف وحذف كل البيانات المحلية
```

ملف `docker-compose.override.yml` يُحمَّل تلقائياً على جهاز المطوّر، ويشغّل وضع التطوير مع تحديث فوري عند تعديل الكود.

### إذا لم يظهر تعديل جديد في المتصفح

على ويندوز يراقب خادم الواجهة الملفات بالفحص الدوري، وقد يتوقف هذا الفحص بصمت فيبقى المتصفح يعرض نسخة قديمة، حتى لو نجحت الاختبارات. الاختبارات لا تتأثر لأنها تقرأ الملفات مباشرة أو تبني نسخة جديدة.

1. أعد تشغيل خادم الواجهة:
   ```bash
   docker compose restart web          # أو: docker compose up -d --build web
   ```
2. حدّث الصفحة تحديثاً كاملاً: Ctrl+Shift+R.
3. إن بقيت النسخة قديمة، افتح F12 ثم **Application** ثم **Service workers**. في وضع التطوير يجب ألا يوجد أي service worker لـ `localhost`. إن وُجد واحد من تشغيل إنتاجي سابق فاضغط **Unregister**، ثم **Clear site data** من **Storage**، وادخل من جديد.

للتأكد مما يرسله الخادم فعلاً، اطلب الملف المعدَّل وابحث فيه عن نص جديد. مثلاً:

```bash
curl -sk https://localhost/src/layouts/AdminLayout.tsx | grep -o "/admin/archive"
```

## الاختبارات

```bash
docker compose exec api pytest              # اختبارات الخادم
docker compose exec web npm test            # اختبارات الواجهة
scripts/e2e.sh                              # Playwright، وعلى ويندوز: scripts\e2e.ps1
scripts/test-all.sh                         # كل الفحوصات، وعلى ويندوز: scripts\test-all.ps1
bash scripts/backup-e2e.sh                  # النسخ والاسترجاع والتجربة والهارد (جهازك فقط)
bash scripts/deploy-e2e.sh                  # فحوص سكربت النشر (جهازك فقط)
```

- اختبارات Playwright تشغّل نسخة منفصلة من التطبيق بقاعدة بيانات فارغة، ثم تحذفها بعد الانتهاء، فلا تتأثر بياناتك المحلية.
- لا تُدمج أي فيزة إلا إذا نجحت كل الفحوصات (مبدأ الدستور VIII).

## التجربة من الهاتف

تجربة الهاتف الحقيقي وتثبيت التطبيق على الشاشة الرئيسية تتم على السيرفر التجريبي `https://sijil.t3cftth.net`، لأن تثبيت التطبيق يحتاج شهادة HTTPS حقيقية. لا تتم عبر الشبكة المحلية.

طريقة النشر (التجريبي والفعلي) موثّقة في [deploy/server.md](deploy/server.md)، والنسخ الاحتياطي والاسترجاع في [deploy/backup.md](deploy/backup.md). على السيرفر يمسك Nginx Proxy Manager المنفذين 80 و443 ويصدر الشهادة، ويوجّه الطلبات إلى حاوية `sijil-web` عبر شبكة Docker، ولا يفتح سِجلّ أي منفذ.

على الكمبيوتر يمكن محاكاة الهاتف من أدوات المطوّر: اضغط F12 ثم Ctrl+Shift+M واختر جهازاً.

## الأمان

- لا ترفع ملف `.env` أو أي مفتاح أو كلمة سر إلى git. ملف `.env.example` يوضح المتغيرات المطلوبة فقط.
- لا تستخدم صور بطاقات حقيقية أو بيانات مشتركين حقيقيين في الاختبارات أو الأمثلة.
- على السيرفر استعمل `scripts/deploy.sh` دائماً (staging وproduction حسب APP_ENV). الأمر `docker compose up` بدون `-f` يحمّل وضع التطوير.

## الرخص

كود سِجلّ (`api/` و`web/` و`e2e/`) خاص. مجلد `ocr/` وحده برخصة **GNU AGPL-3.0** لأنه مبني على
المشروع المفتوح ID_Iraqi_Project؛ هو برنامج مستقل يتكلم معه الخادم عبر HTTP، وكوده مع تعديلاتنا متاح
لمستخدمي التطبيق من «حسابي» ← «رخص البرمجيات المفتوحة».
