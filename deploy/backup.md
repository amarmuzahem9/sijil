# النسخ الاحتياطي والاسترجاع — سِجلّ

هذا الدليل لمن يشغّل السيرفر. القواعد في `docs/system.md` §15، والتفاصيل التقنية في
`specs/016-backup-deploy/`. كل الأوامر تُشغَّل من مجلد المشروع على السيرفر (`/opt/sijil`).

## ماذا يُحفظ، وأين، وكم

| | ماذا | أين | متى | كم يبقى |
|---|---|---|---|---|
| ليلية | قاعدة البيانات كاملة + كل صور البطاقات (ومنها صور القدامى) من نفس اللحظة | `BACKUP_DIR` على السيرفر | كل يوم 03:00 بتوقيت بغداد، تلقائياً | 30 يوماً؛ آخر نسخة ناجحة لا تُمسح أبداً |
| يدوية | نفسها | `BACKUP_DIR` | زر «نسخة يدوية الآن» أو `scripts/backup.sh now` | 30 يوماً |
| قبل النشر / قبل الاسترجاع | نفسها | `BACKUP_DIR` | تلقائياً قبل كل نشر وكل استرجاع | 30 يوماً |
| أسبوعية | آخر نسخة ناجحة | الهارد الخارجي | حين توصله وتشغّل `scripts/backup.sh weekly` | بلا حد؛ سِجلّ لا يمسح شيئاً من الهارد |

- **كل النسخ مشفّرة.** السيرفر يعرف المفتاح العام فقط: يشفّر كل ليلة وحده، لكنه لا يستطيع فتح أي نسخة.
  فتح النسخة يحتاج **كلمة السر** التي تحفظها أنت خارج السيرفر.
- الصورة تُحفظ مرة واحدة وتشترك فيها كل النسخ، فـ 30 نسخة ليلية لا تأخذ 30 ضعف مساحة الصور.
- **لا يدخل أي نسخة:** ملف `.env` وأسراره، وخدمة `ocr` (بلا بيانات)، والكود، وإعدادات Nginx Proxy Manager.
- البيانات الممسوحة بـ «حذف مشترك» تبقى في النسخ حتى تنتهي مدتها: 30 يوماً على السيرفر، وبلا حد على الهارد.

## ⚠️ كلمة السر

- تُكتب مرة واحدة عند `init-key`. **اكتبها على ورق واحفظها في مكان آمن خارج السيرفر** (ونسخة ثانية عند
  صاحب الشركة). لا تضعها في `.env` ولا في git ولا في رسالة.
- **إن ضاعت، لا تُفتح أي نسخة أبداً.** لا يوجد طريق آخر.
- ملف `key.age` (المفتاح محمياً بكلمة السر) موجود في `BACKUP_DIR` وعلى الهارد؛ بدون كلمة السر لا قيمة له.

---

## 1) مجلد النسخ (مرة واحدة)

```bash
sudo mkdir -p /var/backups/sijil
sudo chown 10001:10001 /var/backups/sijil
sudo chmod 700 /var/backups/sijil
```

وفي `.env`: `BACKUP_DIR=/var/backups/sijil`. السكربت يرفض النشر إن لم يكن المجلد للمستخدم 10001 بصلاحية 700.

## 2) المفتاح (مرة واحدة)

```bash
bash scripts/backup.sh init-key
```

- يسألك `age` عن كلمة السر. **اضغط Enter** ليقترح كلمة سر قوية من 10 كلمات، واكتبها على الورق.
- يطبع سطراً مثل `BACKUP_AGE_RECIPIENT=age1...`؛ ضعه في `.env` (هذا مفتاح عام، ليس سراً).
- لا يمكن تشغيله مرة ثانية فوق مفتاح موجود (حتى لا تضيع النسخ القديمة).

ثم `bash scripts/deploy.sh` ([server.md](server.md)). من الآن تعمل خدمة `sijil-backup` وتنسخ كل ليلة.

## 3) المتابعة اليومية

- صفحة **«النسخ الاحتياطي»** في التطبيق (الأدمن الرئيسي فقط): آخر نسخة، النسخ المحفوظة، آخر نسخة على
  الهارد، آخر تجربة استرجاع، المساحة، وآخر عمليات النشر. الاسترجاع **ليس** في الصفحة.
- أي مشكلة تظهر تحذيراً أحمر في الصفحة وفي رئيسية الأدمن الرئيسي (الجدول في آخر الدليل).
- من الطرفية: `bash scripts/backup.sh status` (رمز الخروج 1 إن وُجد تحذير)، و`bash scripts/backup.sh list`.

## 4) الهارد الخارجي — كل أسبوع (يُستحسن الجمعة)

**أول مرة لكل هارد:**

```bash
sudo mkdir -p /media/sijil-external
sudo mount /dev/sdX1 /media/sijil-external        # اسم القرص من: lsblk
sudo chown 10001:10001 /media/sijil-external
bash scripts/backup.sh init-external               # يكتب علامة .sijil-external على الهارد
```

وفي `.env`: `BACKUP_EXTERNAL_DIR=/media/sijil-external`.

**كل أسبوع:**

```bash
sudo mount /dev/sdX1 /media/sijil-external
bash scripts/backup.sh weekly
sudo umount /media/sijil-external                  # بعد «يمكن فصل الهارد الآن» فقط
```

`weekly`:
1. يرفض إن لم يكن المسار هارداً مركّباً عليه العلامة (فلا يكتب على قرص السيرفر بالغلط).
2. يتأكد من المساحة، ثم ينسخ آخر نسخة ناجحة والصور الجديدة فقط و`key.age`، ثم يعيد قراءة كل ملف ويقارنه.
3. **لا يمسح ولا يبدّل أي شيء على الهارد.**
4. يجري **تجربة استرجاع من النسخة التي على الهارد** (يسألك كلمة السر).
5. يطبع «يمكن فصل الهارد الآن».

احفظ الهارد في مكان مقفل خارج غرفة السيرفر. بدون كلمة السر لا يُقرأ منه شيء.

## 5) تجربة الاسترجاع

تجري تلقائياً داخل `weekly`، ويمكن تشغيلها وحدها:

```bash
bash scripts/backup.sh drill                  # آخر نسخة على السيرفر
bash scripts/backup.sh drill --external       # من الهارد (يجب أن يكون مركّباً)
```

تسترجع النسخة في نسخة مؤقتة معزولة: **بلا شبكة** (لا رسائل OTP، لا Google)، ولا يصلها أي مستخدم، ولا تلمس
التطبيق الحقيقي. تقارن الأعداد وكل صورة، ثم تُمسح بالكامل. النتيجة فقط (نجحت/فشلت والأعداد) تظهر في الصفحة.

## 6) الاسترجاع الفعلي

**متى:** فقدان بيانات، خطأ كبير، أو نشر غيّر البيانات وفشل. ليس لتصحيح طلب واحد.

```bash
bash scripts/backup.sh list                   # اختر النسخة
bash scripts/restore.sh 20261127-000000-nightly
bash scripts/restore.sh                       # بلا رقم = آخر نسخة
bash scripts/restore.sh <رقم> --from-external  # من الهارد (مركّباً)
```

ما يحدث:
1. يعرض النسخة (وقتها بتوقيت بغداد وأعدادها) و**ما سيضيع**: كل ما حدث بعدها، وأي «حذف مشترك» بعدها يرجع.
2. يطلب أن **تكتب تاريخ النسخة** للتأكيد. أي تاريخ آخر = لا يتغيّر شيء.
3. يفحص النسخة (كاملة، غير تالفة، ليست من إصدار أحدث من الكود). أي مشكلة = لا يتغيّر شيء.
4. يأخذ نسخة **«قبل الاسترجاع»** من الوضع الحالي، فيمكن الرجوع إليه.
5. يسأل كلمة السر، يفك الصور ويفحصها في مكان مؤقت، ثم فقط يوقف التطبيق، يعيد قاعدة البيانات والصور،
   ويشغّله ويتأكد من صحته. خلال هذه الدقائق يرى المستخدمون «تعذّر الاتصال، حاول مرة أخرى».
6. يسجّل الاسترجاع في الصفحة وفي سجل العمليات.

الجلسات المفتوحة قد تنتهي فيسجّل المستخدمون الدخول من جديد.

## 7) الاسترجاع على سيرفر جديد (ضاع السيرفر)

تحتاج: **الهارد الخارجي** و**كلمة السر**. لا تحتاج `.env` القديم.

1. جهّز السيرفر الجديد كما في [server.md](server.md) الخطوات 1–3، واكتب `.env` جديداً من `.env.example`
   بأسرار جديدة (كلمة سر قاعدة البيانات، `JWT_SECRET`). مفاتيح OTPIQ وGoogle Maps تُعاد من لوحاتها.
2. مجلد النسخ (الخطوة 1 هنا). **لا تشغّل `init-key`**: انسخ `key.age` من الهارد إلى `BACKUP_DIR`
   (`sudo cp /media/sijil-external/key.age /var/backups/sijil/ && sudo chown 10001:10001 …`)، واستخرج
   المفتاح العام منه لـ `.env`:
   ```bash
   docker run --rm -it -v /var/backups/sijil:/k alpine sh -c 'apk add -q age && age -d /k/key.age | age-keygen -y'
   ```
3. `bash scripts/deploy.sh` (يبدأ بتطبيق فارغ).
4. ركّب الهارد و`BACKUP_EXTERNAL_DIR` في `.env`، ثم: `bash scripts/restore.sh --from-external`.
5. أعد Proxy Host في NPM ([server.md](server.md) الخطوة 5).

## 8) فتح نسخة يدوياً (بدون سِجلّ)

للطوارئ فقط، على جهاز موثوق بلا شبكة إن أمكن. أي جهاز عليه `age` و`pg_restore` 16:

```bash
age -d -o identity.txt key.age                                # يسأل كلمة السر
age -d -i identity.txt -o db.dump snapshots/<رقم>/db.dump.age  # قاعدة البيانات (pg_restore -l db.dump)
age -d -i identity.txt -o x.jpg images/<اسم>.jpg.age          # صورة
shred -u identity.txt db.dump x.jpg                           # امسح كل ما فُتح
```

`manifest.json` في كل نسخة يذكر الصور التي تحتاجها، بلا أي بيانات شخصية.

## 9) التحذيرات وماذا تفعل

| التحذير | السبب | ماذا تفعل |
|---|---|---|
| خدمة النسخ متوقفة | لا نبضة من `sijil-backup` منذ 10 دقائق | `sijil ps backup`، `sijil logs backup`، `sijil up -d backup` |
| لم يُضبط مفتاح النسخ | `BACKUP_AGE_RECIPIENT` فارغ | الخطوة 2 |
| فشل آخر نسخ احتياطي | انظر السبب في الصفحة | «المساحة غير كافية» → وفّر مساحة (`df -h`)؛ غيره → `sijil logs backup` ثم «نسخة يدوية الآن» |
| لا توجد نسخة ناجحة منذ أكثر من 36 ساعة | الخدمة متوقفة أو كل المحاولات تفشل | كما سبق؛ النسخة الليلية تُعاد بعد ساعة، 3 مرات في اليوم |
| مساحة السيرفر قليلة | الفارغ أقل من ضعف `BACKUP_MIN_FREE_GB` | وفّر مساحة قبل أن يُرفض النسخ |
| تجربة الاسترجاع فشلت أو متأخرة | فشلت، أو لا تجربة منذ 8 أيام | `bash scripts/backup.sh drill`؛ إن فشلت اقرأ السبب ولا تعتمد على تلك النسخة |
| النسخة الأسبوعية على الهارد متأخرة | لا نسخة على الهارد منذ 8 أيام | الخطوة 4 |

## رموز الخروج

| الأمر | الرمز | المعنى |
|---|---|---|
| `backup.sh now` | 3 / 4 | نسخ آخر جارٍ / المساحة غير كافية |
| `backup.sh weekly` | 5 | الهارد غير مركّب، بلا علامة، ممتلئ، أو فشل النسخ عليه |
| `backup.sh weekly` / `drill` | 6 | فشلت تجربة الاسترجاع |
| `restore.sh` | 7 | رُفض (تاريخ غير مطابق، نسخة تالفة أو من إصدار أحدث، كلمة سر خاطئة) |
