# التجربة اليدوية — الفيزة 008: فحص الطلب والقرار عند الإرسال

التجربة على `https://localhost` بمجموعة التطوير. استعمل بطاقتك أنت فقط من جهازك، ولا ترفعها لأي مكان ثاني.

## قبل البدء

1. شغّل التطبيق: `docker compose up -d`. بعدها تأكد بـ `docker compose exec api alembic current`، والنتيجة لازم تكون `0010 (head)`.
2. **كلفة الرسائل:** كل «تحقّق» ناجح على OTPIQ يكلّف 25 دينار، والتجربة كاملة تحتاج 4 رسائل تقريباً.
   - حتى توفّر الرصيد محلياً، حط بملف `.env` السطرين `OTP_MODE=fake` و`OTP_FAKE_CODE=246810`، ثم شغّل `docker compose up -d api`. هيج يكون الرمز دائماً 246810 وما تنرسل رسالة.
   - رجّع السطرين لحالتهم بعد التجربة. السيرفر يرفض هذا الوضع على staging وproduction.
3. لازم يكون عندك من الإعدادات: منطقة، وبرج تابع لها، وفئة.
4. **الطلب المُرسل ما ينحذف من التطبيق.** آخر هذا الملف فيه أمر يمسح بيانات التجربة من جهازك فقط.

| # | الخطوة | النتيجة المتوقعة |

## فحص عدم التسرّب

1. `docker compose logs api | grep "submit draft"`: يطلع سطر لكل محاولة فيه النتيجة ورقم الطلب، والهاتف مخفي مثل `0780****567`، بلا رقم وطني ولا رقم عائلي ولا اسم.
2. سجل العمليات (بحساب الأدمن الرئيسي): يظهر «إرسال طلب» لكل طلب، و«رفض إرسال طلب» لكل رفض بسبب الهاتف أو الرقم الوطني. التفاصيل فيها الرقم والنوع والحالة والأسباب والبرج والفئة فقط.
3. بالمتصفح افتح أدوات المطوّر، ثم Network، وراجع ردود المسودة: نتيجة الفحص تظهر كـ `checks` بقيم true/false فقط، بلا اسم أو يوزر أو برج للمشترك الثاني.
