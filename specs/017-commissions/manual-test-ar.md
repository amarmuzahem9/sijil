# التجربة اليدوية — الفيزة 017: المكافآت والعمولات

التجربة على `https://localhost` بمجموعة التطوير على جهازك فقط. أرقام وأسماء وهمية فقط، وبلا صور بطاقات حقيقية.

## قبل البدء

1. شغّل `docker compose up -d`، وبعدها `docker compose exec api alembic current`. النتيجة لازم تكون `0020 (head)`.
2. الشرائح الافتراضية بـ «الإعدادات» ← «الشرائح»: 0 ← 5,000، و30 ← 7,000، و50 ← 10,000. الحسابات بالأسفل مبنية عليها.
3. الحسابات، يسويها الأدمن الرئيسي:
   - «أدمن العمولات»: صلاحية «العمولات وزر تم الدفع»، ويّاها «تم الربط والتراجع عنه».
   - «أدمن الربط»: «تم الربط والتراجع عنه» فقط.
   - «أدمن المسوّقين»: «إدارة المسوّقين» فقط.
   - مسوّقين: «المسوّق الأول» و«المسوّق الثاني».
4. **أشهر سابقة**: التطبيق دائماً يربط بالوقت الحالي، فالربط بالشهر السابق يتسوّى بأمر على قاعدة البيانات المحلية. سوّيه على طلبات تجريبية بس. بدّل `1001` برقم الطلب:

   ```
   docker compose exec -T db psql -U sijil -d sijil -c "update requests set linked_at = linked_at - interval '1 month' where number = 1001; update request_links set at = at - interval '1 month' where request_id = (select id from requests where number = 1001) and kind = 'linked';"
   ```

## 1. رئيسية المسوّق: الشريحة والمبلغ المتوقع

| # | الخطوة | النتيجة المتوقعة |
|---|---|---|
| 1 | ادخل كالمسوّق الأول وما عنده ربط هذا الشهر | «تم الربط هذا الشهر: 0»، «الشريحة الحالية: 5,000 د.ع للمشترك»، «المبلغ المتوقع: 0 د.ع»، «عندك 0، باقيلك 30 وتصير 7,000 للمشترك» |
| 2 | كأدمن الربط، اربط 3 طلبات مقبولة للمسوّق الأول، وحدّث رئيسيته | «تم الربط هذا الشهر: 3»، «المبلغ المتوقع: 15,000 د.ع»، «باقيلك 27» |
| 3 | اقبل طلب عودة بـ «لا» للعمولة للمسوّق الأول، واربطه | يطلع «و 1 بلا عمولة»، والمبلغ يبقى 15,000 |
| 4 | كأدمن رئيسي، غيّر أول شريحة لـ 6,000 واحفظ. حدّث رئيسية المسوّق | «6,000 د.ع للمشترك» و«المبلغ المتوقع: 18,000 د.ع». بعدها رجّعها 5,000 |
| 5 | لو تكدر تخلي مسوّق يوصل 50 ربط (أو انزّل حد آخر شريحة لـ 3 مؤقتاً) | سعر أعلى شريحة، وما يطلع سطر «باقيلك». رجّع الشرائح بعدها |

## 2. «الأشهر السابقة» للمسوّق

| # | الخطوة | النتيجة المتوقعة |
|---|---|---|
| 1 | رجّع طلبين من طلبات المسوّق الأول المربوطة شهر لورا بأمر «قبل البدء» | الرئيسية تنقص 2 |
| 2 | كالمسوّق، اضغط «الأشهر السابقة» من الرئيسية | كرت للشهر السابق فيه «تم الربط: 2» و«2 × 5,000 د.ع = 10,000 د.ع» و«غير مدفوع». الشهر الجاري ما يطلع هنا |
| 3 | ادخل كالمسوّق الثاني وافتح «الأشهر السابقة» | «لا توجد أشهر سابقة». ما يشوف أشهر المسوّق الأول |
| 4 | كأدمن، افتح `https://localhost/commissions` | ما تنفتح، لأن الصفحة للمسوّق بس |

## 3. تقرير «العمولات»

| # | الخطوة | النتيجة المتوقعة |
|---|---|---|
| 1 | ادخل كأدمن العمولات | «العمولات» بالقائمة بعد «الاستيراد». الصفحة تنفتح على الشهر الجاري ويّا «الشهر الجاري، يُسجَّل الدفع بعد نهايته» |
| 2 | اختار الشهر السابق | كرت المسوّق الأول: «2 × 5,000 د.ع = 10,000 د.ع» و«غير مدفوع»، و«مجموع الشهر» يساوي مجموع الكروت |
| 3 | اضغط «التفاصيل» | «المحسوبة (2)» بالرقم والاسم والنوع والبرج وتاريخ الربط. **ما في هاتف ولا يوزر ولا رقم وطني ولا رقم عائلي ولا صور** |
| 4 | قارن أرقام الكرت ويّا «الأشهر السابقة» عند المسوّق، وأرقام الشهر الجاري ويّا رئيسيته | متطابقة |
| 5 | أوقف المسوّق الأول من «المسوّقون»، وارجع للتقرير | كرته يبقى باسمه. بعدها فعّله |
| 6 | ادخل كأدمن الربط | «العمولات» ما تطلع بالقائمة، وفتح `/admin/commissions` مباشرة يرجعك ويطلع «ليست لديك صلاحية» |

## 4. «تم الدفع» وقفل الشهر

| # | الخطوة | النتيجة المتوقعة |
|---|---|---|
| 1 | بالشهر الجاري | ماكو زر «تم الدفع» على أي كرت |
| 2 | بالشهر السابق اضغط «تم الدفع» على كرت المسوّق الأول، وبعدها «إلغاء» | النافذة تبين اسم المسوّق والشهر و«2 × 5,000 د.ع = 10,000 د.ع» و«لا يمكن التراجع عن الدفع». الإلغاء ما يغيّر شي |
| 3 | «تم الدفع» ثم «تأكيد الدفع» | الكرت يصير «تم الدفع»، وتحته «تم الدفع بواسطة أدمن العمولات» والوقت، والزر يختفي |
| 4 | افتح «سجل العمليات» كأدمن رئيسي | «تسجيل دفع عمولة» ويّا «عمولة المسوّق الأول — الشهر» والعدد والسعر والمبلغ. بلا أسماء مشتركين ولا أرقام طلبات |
| 5 | غيّر أول شريحة لـ 6,000 | الشهر المدفوع يبقى «× 5,000 د.ع»، والشهر الجاري يصير «× 6,000 د.ع». رجّعها 5,000 |
| 6 | كالمسوّق افتح «الأشهر السابقة» | الشهر السابق «تم الدفع» بأرقامه المقفلة، بلا اسم الأدمن |
| 7 | **الضغط بنفس اللحظة**: رجّع طلب للمسوّق الثاني للشهر السابق. افتح «العمولات» على الشهر السابق بتبويبين. اضغط «تم الدفع» ثم «تأكيد الدفع» على كرته بالتبويب الأول، وبعدها بالثاني بدون تحديث | الثاني يطلعله «تم تسجيل الدفع لهذا الشهر مسبقاً»، وسجل العمليات بيه سطر واحد بس |
| 8 | **تغيّر الأرقام**: رجّع طلبين للمسوّق الثاني لشهر قبل اثنين (`interval '2 months'`). افتح «تم الدفع» على كرته وخلّي النافذة مفتوحة. بتبويب ثاني تراجع عن ربط واحد منهم من «بانتظار الربط» ← «المربوطة مؤخراً». ارجع واضغط «تأكيد الدفع» | «تغيّرت الأرقام، راجعها من جديد»، والكرت يتحدّث برقم أقل وما ينحفظ دفع |
| 9 | كرت عدده صفر (عنده بس عودة بـ «لا» بشهر سابق) | ماكو زر «تم الدفع» |

## 5. التراجع بعد الدفع

| # | الخطوة | النتيجة المتوقعة |
|---|---|---|
| 1 | كأدمن العمولات، تراجع عن ربط واحد من طلبات الشهر المدفوع، بسبب «لم يُربط فعلياً في SAS» | يصير التراجع عادي، ويوصل المسوّق إشعار التراجع مثل 013 |
| 2 | افتح «العمولات» على الشهر المدفوع | الأرقام نفسها «2 × 5,000 د.ع»، ويطلع تنبيه أصفر «تراجع بعد الدفع · المدفوع 2، اليوم 1» وتحته رقم الطلب والوقت و«لم يُربط فعلياً في SAS» |
| 3 | افتح الرئيسية كأدمن رئيسي، وكأدمن العمولات، وكأدمن الربط | الأولين يطلعلهم «يوجد تراجع بعد الدفع» ويّا رابط «صفحة العمولات». أدمن الربط ما يطلعله |
| 4 | اربط نفس الطلب مرة ثانية | بالشهر الجاري: كرت المسوّق «مدفوع سابقاً: 1» والمبلغ ما يزيد، وبالتفاصيل تحت «مدفوع سابقاً» ويّا «دُفع في» والشهر. رئيسية المسوّق تحسبه «بلا عمولة». تنبيه الشهر المدفوع يبقى |
| 5 | رجّع وقت التراجع 31 يوم لورا: `docker compose exec -T db psql -U sijil -d sijil -c "update request_links set at = at - interval '31 days' where kind = 'unlinked' and request_id = (select id from requests where number = 1001);"`، وحدّث الرئيسية | يختفي التحذير من الرئيسية، والتنبيه يبقى بصفحة العمولات |

## 6. صفحة «المسوّقون»

| # | الخطوة | النتيجة المتوقعة |
|---|---|---|
| 1 | ادخل كأدمن المسوّقين وافتح «المسوّقون» | عمود «هذا الشهر» فيه «عدد الشهر: N · العمولة المتوقعة: …» لكل مسوّق. على الهاتف يطلع تحت الاسم |
| 2 | قارن ويّا رئيسية كل مسوّق | متطابقة. المسوّق اللي ما عنده ربط هذا الشهر «0 · 0 د.ع» |
| 3 | دوّر على زر «تم الدفع» | ما موجود بهالصفحة |

## 7. اللي ما ينحسب أبداً

| # | الخطوة | النتيجة المتوقعة |
|---|---|---|
| 1 | طلب بالانتظار، وطلب مرفوض، وطلب مقبول ما انربط | ما يطلعون بأي عدد ولا تقرير |
| 2 | احذف طلب بالانتظار (011) | ما يتغيّر أي عدد |
| 3 | استورد ملف مشتركين قدامى وملف SAS تجريبيين (014، 015) | ما يتغيّر أي عدد ولا أي كرت بالعمولات |
