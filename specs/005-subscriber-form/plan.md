# Implementation Plan: New Subscriber Form (single page)

**Branch**: `005-subscriber-form` | **Date**: 2026-11-22 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/005-subscriber-form/spec.md` and the owner's plan
input: the tables, the autosave protocol with `version` and 409, browser compression, the
private uploads volume, the image endpoint, deletion with files, the satellite map,
reconciliation with the catalog, the tests, and the staging docs.

## Summary

Marketers fill one page that saves itself to the server as a draft.

**Data**:
- New tables: `drafts`, `draft_images`, `image_access_log`. The draft PK is a UUID generated by
  the client. Settings FKs use `SET NULL`.
- Each draft stores copies of the names and prices, which the server fills from the catalog.
  The client never sends prices.
- A `version` counter and the id of the last session give "last save wins" with a 409 notice on
  the other device.

**Behaviour**:
- **Images**: compressed in the browser (1600px, JPEG 0.8). They are uploaded with
  `XMLHttpRequest` for progress and retry, and stored as `<uuid>.jpg` in the private `uploads`
  volume. They are served only through a permission-checked endpoint, and every open is logged.
- **Delete**: removes the rows and the files and is audited without card data.
- **Map**: the key and map ID come from the server at runtime (`/api/client-config`). Without a
  key the form still works through GPS.

**Web**:
- The new-subscriber page with its five sections, the save badge, the «النواقص» summary, and a
  disabled «إرسال».
- `/requests` gets its tabs, with «مسودات» filled.

Details: [research.md](./research.md).

## Technical Context

**Language/Version**: Python 3.12 (api); TypeScript + React 18 (web), unchanged

**Primary Dependencies**:
- api: + `python-multipart` (FastAPI uploads), + `Pillow` (verify the image and read its size,
  reused by 006 OCR).
- web: none new. Google Maps is loaded by its official bootstrap script, not an npm package.

**Storage**:
- PostgreSQL 16, migration `0005_drafts` with 3 tables.
- Files in the Docker volume `uploads` (`sijil_uploads`), mounted at `/data/uploads` in `api`
  only.

**Testing**: pytest (real PostgreSQL, temporary `UPLOADS_DIR` per test), Vitest, Playwright
(desktop, Pixel 7, iPhone 14; two contexts for the acceptance test)

**Target Platform / Project Type**: Unchanged web app (`api/` + `web/`), PWA on iPhone and Android
browsers

**Performance Goals**:
- A change is saved in ≤ 5 s (SC-002).
- The other device is notified in ≤ 30 s, through 15-second polling (SC-004).
- One card side is about ≤ 600 KB and uploads in under 10 s on a slow connection (SC-003).

**Constraints**:
- Card data is never stored in localStorage or the service worker, and never appears in logs or
  audit entries (Principle II).
- Images are served only by the API with `no-store`.
- The upload limit is 5 MB, enforced in the API. Nginx Proxy Manager needs
  `client_max_body_size 6m`.
- CSP is extended only for Google's map hosts.

**Scale/Scope**:
- About 9 API routes and 3 tables.
- Web: 1 form page with 5 sections and the requests page with its tabs.
- Tens of drafts per marketer.

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

| Principle | Status | How this plan complies |
|---|---|---|
| I. Anti-Fraud | ✅ | No decision is made. The phone is normalized per §8.1 and the national ID by the canonical rule, ready for 008. The send button stays disabled |
| II. Identity Documents | ✅ | Images sit in a private volume outside the web root and have random names. They are served only via the API after an owner, main-admin or `review` check, with `no-store`. Every open is logged (R7). Re-encoding strips EXIF. There is no card data in logs, audit entries, localStorage or the SW cache |
| III. Audit Trail | ✅ | `draft.deleted` is audited without card data. Draft deletion is allowed by constitution 1.1.1 and system.md §5 v1.4. The image access log is append-only and outlives deletion |
| IV. Immutable Values | ✅ | The server copies names and prices on every draft save from the catalog. They become final at submission (008). Requests are untouched |
| V. Mobile & Arabic | ✅ | Compression on the device, autosave with retry, Arabic messages, an RTL single page, camera capture on phones |
| VI. Simplicity | ✅ | Last save wins (no merging), polling instead of sockets, one file per side, no offline store |
| VII. Fixed Stack | ✅ | No framework change. Two small api libraries are justified (R6). The map sits behind `lib/googleMaps.ts` with a "no map" fallback that tests use as the fake |
| VIII. Tests | ✅ | The owner's tests (ownership, 409, deletion of files, compression, validation, two-context acceptance), plus copies, the access log and log safety |
| IX. Server Authorization | ✅ | `require_roles("marketer")` plus the owner check on every draft route. The image route checks owner, main admin or `review`. A foreign draft gets 404 |
| X. Time | ✅ | UTC storage. The drafts list shows Baghdad time |

**Result**: PASS before research and after design. There are no violations.

**Notes for the owner**:
- Image access is logged for every viewer, including the owner, not only admins. Principle II
  requires "every access".
- The volume is named `sijil_uploads` rather than `sijil-uploads`, to stay isolated from the
  e2e stack (R7).

**Structure Decision**:
- Drafts get their own model, service and router, following the 004 pattern.
- File handling is isolated in `image_store.py`, so 006 (OCR) and 008 (moving images to
  requests) reuse it.
- The form is a folder of section components under `pages/marketer/subscriber/`, driven by one
  autosave hook.
